## 구조와 실행

- 독립 정적 사이트: HTML·CSS·일반 JavaScript. Python 표준 라이브러리는 loopback 미리보기 서버에만 사용한다.
- 메인 `index.html`, BatteryFlow 상세 `batteryflow.html`, 부산 약국 상세 `busan-night-pharmacy.html`, 새 상세용 `project-template.html`. 프로젝트 목록은 `projects.js`, 공통 동작은 `site.js`, 디자인은 `styles.css`다.
- 실행은 `start.cmd` 또는 `python serve.py`. 기본 주소 `http://127.0.0.1:8765/`. BatteryFlow 서비스의 가상환경·API·DB는 실행 의존성이 아니다.
- 대표 프로젝트는 order 순 최대 3개. 대표 외 항목이 있으면 전체 목록을 표시하고 분야가 둘 이상일 때 필터를 제공한다.
- 버전은 루트 `VERSION`이 기준이다. HTML의 CSS·JS 캐시 버전과 README·이 문서의 현재 버전을 함께 맞춘다. QA는 버전별 검증 이력을 보존한다.

## 실패 대응과 영상

- 대표 프로젝트 영역에 일반 HTML 상세 링크를 둔다. 대표 데이터가 있고 카드 생성이 성공한 경우만 카드로 교체한다. 데이터 없음·스크립트 실패·카드 생성 오류에서 링크를 유지한다.
- 각 HTML은 site.js 로드 실패 시 즉시, 준비 완료 표시가 없으면 head 실행 후 3초에 js 클래스를 해제한다. 정상 초기화에서는 기존 등장 효과를 유지한다.
- SBS 영상 ID RI5JTzQbqe4, 재생 구간 35–59초. YouTube 플레이어의 autoplay는 0이며 준비 완료 이후 실제 45% 이상 노출일 때 음소거 재생·반복한다. 화면을 벗어나면 일시정지한다.
- 직접 클릭은 45% 조건 없이 소리와 함께 35초부터 재생하고 구간 끝에서 시작 위치로 돌아가 정지한다. 준비 전 클릭은 보관한다. 사용자 재생이 일시정지된 뒤에는 재노출만으로 자동 재개하지 않는다.
- 중복 플레이어 생성을 막는다. HTTP origin 없음·오류·10초 타임아웃 시 원본 링크로 전환하며, 이후 늦은 API 응답·이벤트는 무시하고 반복 타이머를 정리한다.

## 부산 심야약국 상세 페이지

기존 사례의 헤더·본문·표·접기 형식을 재사용한다. 본인 역할과 AI 구현 지원은 첫 화면에 표시한다. 추가 전후 지도는 버튼의 aria-pressed, 이미지 대체텍스트와 캡션이 함께 바뀌며 JavaScript가 없으면 원본 링크로 열람한다. 실제 화면 캡처를 사용하고 모바일 두 화면은 작은 화면에서 세로 배치한다.

분석 수치는 10-13 수집·10-14 위치 보정 기준이며 이후 API 검사는 분석 갱신과 구분한다. 현재 화면은 기준일 데모이며 실제 이용자 수·현장 검증·최적 입지 확정·ML 예측 실적으로 표현하지 않는다. 공개 소스 저장소로 연결하고 공개용 수치 근거는 이 사이트 내부에 포함한다.

## v0.3.2 전력 분석의 판단·트러블 슈팅 · 2026-10-15

Q1 → Q2·LSTM 비교 → Q3 실험 → 최종 Q2 선택을 네 단계 경로와 문제·시도·검증·선택 이유로 표시한다. Q3의 개발 고전력 개선·보호 조건 통과와 Q2의 기존 Q1 교체 조건 미충족을 구분하며 대표 선택의 9월 회고 맥락을 공개한다. 개인 판단·팀원 접근·Codex/Claude Code 구현을 분리한다.

반복 프로파일·근무 리듬 그림을 열린 본문에 배치하고 점심·저녁 교차검증에서 전력 열을 일괄 이동하지 않은 판단을 설명한다. 이전 1시간 최대값 기상 누출 수정 범위를 명시한다. 실패·경보는 하나의 절로 묶고 성능과 부담은 모바일 HTML 수치로 함께 표시한다. 메인 카드 라벨을 문제/내 역할/핵심 판단으로 통일한다.

공개 기여 JSON의 편집 메모와 내부 저자 확인 필드를 제거하고 수치·검증 범위는 보존한다. 편집 근거는 웹 루트 밖의 분석 작업 공간에 둔다. 기존 모델·학습 데이터·제출 문서는 수정하지 않는다. 디자인·글꼴·색상은 기존 사례 형식을 유지한다.

## v0.3.3 전력 사례의 판단·실험 설명 압축 · 2026-10-15

스타일과 9개 그림의 위치·캡션·원본 링크는 유지한다. 기상 누출은 예측 당시 알 수 없던 값이 입력됐다는 영향부터 설명한다. 개인 기여는 시간 기준 검증·신규 프로파일 평가·경보 지속시간과 발생 횟수의 동시 검토를 앞세운다.

네 단계 카드는 문제·시도·검증·판단을 짧게 유지하고 반복 역할·설정·정확한 개발 수치는 기존 상세 접기로 옮긴다. 마지막 단계는 제출 대표 모델 Q2로 명명한다. 개발 교체 조건 미충족 → 9월 회고 선택 → 새 기간 검증 필요를 열린 강조 문단에서 연결한다. Q3의 개선 기준은 Q1이며 개발 보호 조건 통과를 유지한다. 수치·모델·이미지·공통 스타일은 변경하지 않는다.

## v0.3.4 BatteryFlow 역할·평가 범위·모바일 확대 · 2026-10-15

BatteryFlow 첫 화면에 최종 ERP 발주 계획량이라는 대상, 기간별 성능을 고려한 계획 검토 기준선 판단, 본인·팀원·생성형 AI 구현 지원을 표시한다. 성능표는 12개 목표일·112개 부품·1,289행·3개 시간순 CV 구간 합산이며, 마지막 7개 목표일 회고와 별도로 설명한다. 기존 성능·신뢰구간·원본 근거는 변경하지 않는다.

페이지 전용 batteryflow.css로 SUIT·색·기존 사례 스타일을 유지한다. 모바일에서는 원본 PNG를 CSS로 잘라 예측·계획·차이 카드, Copilot 답변·검토 링크, 핵심 시스템 모듈을 확대한다. 긴 Copilot 답변은 가로 스크롤로 읽는다. 파일의 픽셀은 편집하지 않으며 모든 그림에 전체 원본 링크를 유지한다. 데스크톱·인쇄에서는 전체 이미지가 보인다. 페이지 전용 스타일도 배포 대상에 포함한다.

## v0.4.0 채용 담당자 시점의 압축 · 2026-10-17

- 상세 페이지 첫 화면: 태그라인(결과 중심) → 한 줄 설명 → 메타 → 역할 표(`.case-roles` 또는 기존 역할 목록) → 핵심 수치 카드 3개(`.case-stats`, 전력은 기존 `.power-overview`) → 액션.
- 본인·팀원·AI 역할 구분은 첫 화면 표 한 곳에만 둔다. 섹션 라벨·그림 캡션에 역할 문구를 반복하지 않는다.
- 열린 본문은 판단과 결과만 담는다. 신뢰구간·평가 규모·가정·현장 미검증 같은 해석 범위는 페이지 맨 아래 접기에 한 번만 적는다.
- 메인 카드 라벨은 문제 / 내 역할 / 결과다.
- 전력 페이지 용어: 기준 모델(Q1) / 제출 모델(Q2) / 피크 특화 모델(Q3), 고전력 → 피크 구간, 신규 프로파일 → 처음 보는 패턴. 대응표는 '모델 선택 과정과 개발 수치' 접기에 둔다. 약점(피크 구간 오차 증가·교체 기준 미충족·9월 회고 선택)은 03의 회고 문단에서 공개한다.
- 부산 페이지는 새 태그라인 아래 기존 문장을 부제(`.case-subline`)로 유지한다.
